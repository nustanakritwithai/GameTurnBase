# คู่มือส่งงานสไปรต์ — สำหรับคนวาด

> ทำตามหน้านี้แล้วชุดจะเข้าเกมได้ตั้งแต่ครั้งแรก
> เกณฑ์ทั้งหมดมาจาก `docs/SPRITE-DESIGN-LOCK.md` · สถานะปัจจุบันของอาร์ตในเกมอยู่ที่ `docs/SPRITE-CONFORMANCE.md`
> ปรับปรุง 2026-08-11

**อย่าเปิดอาร์ตเก่าในรีโปแล้วเลียนแบบ** — ผืนในนั้นมีแปดขนาด และมีสามชุดที่ไม่ผ่านเกณฑ์ปัจจุบัน หน้านี้คือตัวอ้างอิง ไม่ใช่ไฟล์ที่ ship อยู่

---

## ส่งอะไรมา

```
เดิน       8 ทิศ x 8 เฟรม = 64 ไฟล์   ผืน 640 x 512 RGBA   <prefix>-<ทิศ>-<0..7>.webp
หันทิศ     8 ไฟล์                      ผืน 396 x 376 RGBA   <prefix>-<0..7>.webp
ยืนเฉย     24 ไฟล์                     ผืน 396 x 376 RGBA   <prefix>-<0..23>.webp
บีบ        npm run build:images
วางไฟล์    PNG ต้นฉบับ -> assets/raw/  ·  WebP ที่ ship -> public/
```

**ผืนไม่เท่ากันทุกชุด และนั่นถูกต้อง** ชุดเดินอยู่บนผืนใหญ่กว่าเพราะตัวละครกินพื้นที่มากกว่าตอนก้าว ส่วนหน้าทำเนียบวีรชนตรึงอัตราส่วน `396/376` ไว้ ถ้าส่ง idle/turn มาเป็น 640×512 หน้านั้นจะเพี้ยนทันที

### ชุดหันทิศนับด้วยเลข ไม่ใช่ชื่อ

```
0  down          4  up
1  down-right    5  up-left
2  right         6  left
3  up-right      7  down-left
```

**ข้อนี้ผิดแล้วไม่มี error** ตัวละครแค่หันผิดทางทั้งเกม โค้ดหยิบไฟล์จากเลขนี้ตรง ๆ ส่วนชุด**เดิน**นับด้วยชื่อทิศในชื่อไฟล์ — คนละระบบกัน อย่าสลับ

ชื่อทิศของชุดเดิน: `up · up-right · right · down-right · down · down-left · left · up-left`

## จุดยึด — ส่วนที่ยากที่สุด และตรวจง่ายที่สุดว่าใครทำมาดี

**จุดยึดคือ bottom-center อยู่ที่เท้า** — กึ่งกลางแนวนอน ขอบล่าง เกมเรียงหน้า-หลังตามตำแหน่งเท้า เท้าเลื่อน = ลำดับหน้าหลังเลื่อนตาม

### เกณฑ์ที่ต้องผ่าน

| ชนิดท่า                                       | เท้าเลื่อนได้เท่าไร                                             |
| --------------------------------------------- | --------------------------------------------------------------- |
| **ท่ายืน** — ยืนเฉย · หันทิศ · ร่ายอยู่กับที่ | **±1 พิกเซล** ทั้งภายในชุดและข้ามทิศ                            |
| **ท่าเคลื่อนที่** — เดิน · วิ่ง · กระโดด      | ข้ามทิศ **±2 px** · ภายในรอบเดียว **ไม่เกิน 27% ของความสูงตัว** |
| **ท่าแอ็กชัน** — ฟัน · แทง · ยิง              | ข้ามทิศ **±3 px** · ภายในรอบเดียว **ไม่เกิน 23% ของความสูงตัว** |

**ทำไมท่ายืนถึงแน่นที่สุด** เพราะตัวไม่ได้เคลื่อนที่ ไม่มีอะไรใน animation อธิบายได้ว่าทำไมท่าหันซ้ายกับหันขวาถึงยืนคนละระดับ ส่วนท่าวิ่งเท้ายกจริงตามจังหวะ **เลข ±1 ไม่ scale ตามขนาดตัว** — ตัวใหญ่หรือเล็กก็ ±1 เท่ากัน เพราะมันคือความคลาดของการวางงาน ไม่ใช่การเล่าการเคลื่อนไหว

เกณฑ์พวกนี้วัดมาจากคลังอาร์ตสาธารณะสองคลัง 314 ชุด ไม่ใช่ตัวเลขที่คิดขึ้นเอง — ที่มาเต็มอยู่ใน `SPRITE-DESIGN-LOCK.md`

### ชุดต้นแบบอยู่ในรีโปแล้ว

**`spear-warrior-stop-turn`** — เท้าอยู่แถวเดียวกันทุกเฟรม กระจาย **0 พิกเซล** ทั้งสองแกน **ให้ยึดชุดนี้เป็นตัวอย่าง**

**อย่ายึด `monkey-turn`** — กระจาย 51 พิกเซล เกินเกณฑ์ 51 เท่า และมันเป็นแบบนั้นมาตั้งแต่วันวาด ไม่ใช่เพราะใครมาแก้ทีหลัง

## สี่อย่างที่ทำแล้วพัง และไม่มีอันไหนขึ้น error

**เปลี่ยนขนาดผืนเอง** — ไฟล์ชุดหนึ่งถูกใช้โดย renderer **สี่ตัว** ที่มีกรอบต่างกัน แก้ให้ตัวหนึ่งสวย อีกสามตัวเพี้ยนเงียบ ๆ เกิดขึ้นมาแล้วจริง

**ส่งไฟล์ไม่ครบตามจำนวน** — โค้ดสร้างชื่อไฟล์จากตัวเลขที่ปักไว้ ไฟล์ที่ขาดคือ 404 ผู้เล่นเห็นรูปแตก

**เรียงเลขชุดหันทิศผิด** — ตัวละครหันผิดทาง เกมไม่บ่นอะไรเลย

**ส่ง idle น้อยกว่า 19 เฟรม** — ตัวเล่นหยิบเฟรมข้ามทีละ 3 ต่ำกว่านั้นจะวนซ้ำเร็วผิดจังหวะ ธรรมเนียมของเกมนี้คือ **24**

[ ] เท้าอยู่ในเกณฑ์ของชนิดท่า  (ท่ายืน +-1 px — เทียบกับ spear-warrior-stop-turn)
[ ] รัน npm run build:images แล้ว
[ ] ไม่ได้แก้ตารางในโค้ดเอง — ส่งไฟล์มา ฝั่งโค้ดจะปักหมุดให้

**ข้อสุดท้ายมีเหตุผล** ตารางในโค้ดผูกกับ renderer สี่ตัว แก้ตัวเลขในนั้นโดยไม่มีไฟล์รองรับ = เกมยิงหาไฟล์ที่ไม่มีอยู่

## เรื่อง lossless — อ่านก่อนโดนบอกให้แก้

`npm run build:images` บีบแบบ lossy ซึ่งเป็นค่าเริ่มต้นที่ถูก **แต่ตอนนี้ในรีโปมี 5 ชุด รวม 3,546 KiB ที่เป็น VP8L lossless อยู่แล้ว**

เพราะฉะนั้น **ถ้าคุณถูกทักเรื่องนี้ มันไม่ใช่กฎที่คุณคนเดียวพลาด** — เป็นกฎที่ยังไม่เคยถูกบังคับใช้จริง ฝั่งเราต้องเลือกก่อนว่าจะเขียนข้อยกเว้น หรือจะไล่บีบของเก่าให้หมด สิ่งที่ขอจากคุณคือรัน `build:images` เพราะมันลดขนาดได้จริง ไม่ใช่เพราะคุณทำผิดกฎที่คนอื่นทำตาม

---

## ถ้าส่งของที่ไม่ตรงหน้านี้

ไม่เป็นไร แต่**บอกมาว่าต่างตรงไหนและทำไม** ตอนส่ง ผืนใหม่ จำนวนเฟรมใหม่ ชนิดท่าใหม่ — ทั้งหมดรับได้ถ้าฝั่งโค้ดรู้ล่วงหน้า เพราะมีตารางคาลิเบรตต่อชุดไฟล์อยู่แล้วที่ `src/game/realtimeBattle/entitySpritePresentation.ts` ลงทะเบียนผืนใหม่ได้

**ที่รับไม่ได้คือส่งของที่ต่างโดยไม่บอก** เพราะไม่มีอะไรในระบบจะจับได้ จนกว่าจะมีคนเปิดเกมดูแล้วรู้สึกว่าแปลก ๆ
